# BahnMonitor · 德国铁路运行专题

这是 German-Map 与暴力、财产、毒品、移民、环保平级的铁路专题。

## 页面

- `index.html`：复用与主站一致的 OSM 街道底图、Leaflet 缩放、16州和县界及中文城市标签；根据仓库内原始 DB InfraGO 官方轨道 WGS84 线几何绘制**完整基础设施轨道网**（33,547个几何部件），叠加实际观测的绿／橙／红区间；默认区域列车（RE/RB）合并观测。通过 `overview.js` 按选中车类按需加载已发布的区间聚合数据分片，避免把全部运营商脚本同时加载。
- `js/rail-geometry.js`：铁路真实曲线解码、Mercator 投影、包围盒与距离计算；纯工具模块，不请求网络、不创建 UI。投影/选线算法的修改先跑 `tests/unit_core.cjs`。
- `js/rail-analysis.js`：RE/RB 同站间整数计数合并、两种统计分母、风险颜色和同色连续区间链；明确阻止不同路线、分叉或公里断裂拼接，避免将小段百分比求平均。
- `overview.js`：负责 Leaflet 地图、Canvas 绘制、加载调度、用户选择和侧栏更新。纯计算从上述模块调用，不再在大脚本内复制实现。
- `overview.js`：两个 Leaflet Canvas 绘图图层：基础设施全线和有运行观测的区间，避免上一版 4,218 区间 ×2 的 SVG 节点与大量监听器。官方轨道路径在浏览器内一次性解码并进行 EPSG:3857 投影；观察区段在切换筛选时**只重算等级、不重建 SVG 节点**；鼠标点击使用基于几何包围盒的空间桶索引，再以真实线段距离确认命中。
- `overview.css`：保留 German-Map 深色标题/侧栏、统计卡风格，地图区采用与移民、毒品、环保相同的浅色 OSM 街道图。
- `research.html`：完整保留原 v14 研究型仪表盘（包含原线路检索、基础设施和历史观测界面），仍使用 `js/app.js` 等旧版资源。
- `tests/smoke_overview.py`：桌面、手机、区域/长途/其他运营商三组切换、中文站名、热点排名、指标、样本门槛与详情的自动浏览器验收。CI：`.github/workflows/railway-map-smoke.yml`。

## 地图颜色规则（2026年9月）

线段依据历史列车停站配对表现分色，不归因于轨道故障。

- 红色：下游到站晚点达到6分钟的观测比例 **≥40%**，或者到发停靠取消标记涉及比例 **≥8%**。
- 橙色：对应比例 **≥25%** 或 **≥4%**，但未达到红色门槛。
- **绿色**：低于对应警示阈值的真实观测区间；未匹配可靠观测或样本不足的官方铁路底网也以较淡绿色表示，因此绿色不能保证准点。
- 图例直接标注数值范围：**仅晚点**为绿 <25%、橙 25%–<40%、红 ≥40%；**仅停靠取消**为绿 <4%、橙 4%–<8%、红 ≥8%。**综合**使用两项独立的“或”条件：绿为晚点 <25% 且取消 <4%；红为晚点 ≥40% 或取消 ≥8%；橙为有指标达到低门槛但未达到高门槛。两项的分母不同，**不计算也不展示虚假的统一百分比**。
- 每个方向性站间区间的最低样本门槛**固定为100个有效观测**，简洁页面不再提供样本量选择器。底图所有 33,547 个官方轨道几何部件（包括无运行匹配数据的路段）以较淡的绿色完整绘制，确保站间没有观测数据时铁路线仍按**原始官方曲线**可见。绿／橙／红线仅覆盖各类已匹配且样本足够的停站观测几何；不推测无数据的绿色底线的晚点率，不用连接两端点的**臆造直线**补缺。细节按 EPSG:3857 和 OSM 保持坐标一致，缩放时仅跳过显示面积小于像素阈值的中间顶点，原始几何从不改动。

## 来源与局限

- DB InfraGO 2026 官方铁路网 WGS84 线几何；DB Timetables API 在2026年9月的历史停站记录，经 Piet Brömmel 的 [Deutsche Bahn Data](https://github.com/piebro/deutsche-bahn-data) 汇编（CC BY 4.0）。
- 历史到站变更时间可包含预测值；观测是列车**下游站到站表现**，不是区间本身造成的晚点概率。
- 停靠取消标记不等于整趟列车取消、途中终止运行或旅客被滞留的确证。
- **界面仅有三个列车类别：**区域列车（RE/RB）、长途列车（ICE/IC/EC/FLX）和其他运营商（HLB/BRB/ERB/NWB/OE）。各组内依据官方线路编号、起终车站、方向和公里区间匹配后累计原始整数观测量，再计算比例；未匹配不同路段不可合并。其他运营商品牌与区域列车在实际运行服务上可能重叠，因此**不能跨类别加总，也不能作为全国车次占比**。
- 车站名用本地 `js/station-zh.js` 显示常用中文译名；原始德文站名始终保留。未经确认的小站不强行翻译。
- 没有被着色的线路不能理解为准点或没有问题；没有按旅客人数加权，也不构成运营商公平排名。
- 原始9月 Parquet、官方完整原始 CSV 和重算脚本仍以 v14 项目交接包另行保存，不发布到网站。

简洁地图首次点击彩色线段会选中同线路编号、同方向、同风险颜色、站间公里边界相接且无分叉的连续区段，使用**晚点次数/有效到站观测次数**及**停靠取消标记次数/计划配对次数**分别做原始整数合计，再计算比例；禁止把子区间百分比简单平均。连续区段可能重复包含同一列车在多个相邻站间的停站观测，因此展示的是**站间观测加权率**，不是独立整趟车的准点或取消概率。主面板仅呈现“准点率（晚点不足6分钟）”和“停靠取消标记率”，逐站、原始数量和德文站名收纳于可展开的二级详情。

旧版的总体数量统计保留在研究资料中；简洁页面将高关注榜单、研究方法收纳于折叠菜单。原始记录、100次纳入规则与数值警示门槛保持不变。

观察区间高关注榜单按是否超过门槛及相对阈值大小排序，仅用于寻找要关注的地点，不构成全国铁路运行质量的官方排名。

新版本不得修改已公布的事实数据来使地图“更红”。若调整警示阈值，应同步修改 `overview.js`、主页方法说明、本文件和浏览器烟雾测试。

## 全国性无观测区段合并（2026-10-10）

- `js/rail-bridge.js` 根据原始 DB InfraGO 33,547 个轨道几何部件建立按线路编号的空间索引与物理端点图，并使用最短官方曲线路径识别可能连接的缺口。没有任何从站到站凭空生成的直线轨道；若路段交叉、地理走向有歧义、观测颜色冲突、公里区间间隔过大，则不延伸风险颜色。
- 两个方向在同一官方线路、相同公里区间及相同颜色等级上的观测，可统一为一个**物理走廊**。原始到站/取消次数逐项相加后重新计算比例，不能简单平均不同方向或不同站间的百分比；相邻站间可能包含同一列车多次观测，因此这不是独立列车行程的准点/整趟车取消概率。
- 缺少停站观测时有两种处理：**几何已核实**的短缺口可以把官方轨道原始曲线纳入选中高亮（无数据连接绘制为低调绿色，统计分母不增加）；**仅统计合并**的缺口，两端实际观测、线路公里标及官方铁路底网均存在，但由于底网拓扑无法完全追踪连续轨迹，只把两端统计归入同一走廊，不绘制、不点击、不声称中间存在可计量样本，也不把它着红色。
- 一项实证检查是5900号线：菲尔特/埃尔朗根有数据的公里区间7.642—23.504，与福希海姆/希尔斯海德/班贝格的公里区间38.289—62.372间，存在约14.785公里的未覆盖观测范围。该缺口只作为逻辑上的走廊连接，网站首层展示跨端观测合计；中间仍只绘制已经公开的官方绿色轨道，不画补充直线。
- `tests/unit_core.cjs` 和 `tests/smoke_overview.py` 分别验证几何寻路、不同线路及岔路歧义、样本排除、双向数据合计，以及5900号线的真实回归样例。`getBridgedCount()`包含几何连接和仅统计连接，不能直接理解为完全核实的独立官方铁路项目数。

## 全网点击与柏林线路连续性修复（2026-10-10）

- 旧版仅为有足够站间观测的区段建立点击索引：全量官方铁路底网虽然绘制出来，却无法交互。现将官方33,547个真实轨道几何部件加入 `js/rail-picker.js` 的持久空间索引，观测区间使用第二套可切换索引。切换 RE/RB、长途、其他运营商或统计指标时，不得清空官方底网索引。
- 点击带有效观测的绿色/橙色/红色线段仍显示真实汇总数据；点击无可比观测的绿色轨道则只显示“准点率：—”“停靠取消标记率：—”及折叠的数据说明。不能把无数据解释成100%准点或0%停靠取消。
- 相邻相同风险颜色和同官方线路的站间部分，若公里标刚好接壤（此前误被过滤），现在可通过真实几何证据合为单个走廊。连接端点依据**公里标最外端实际观测片段**选取，而不是任意方向列表的第一项/最后一项。岔路及跨轨道走向不明确的地方继续分离，不延伸虚构的颜色。
- 绘制改用圆角线端平滑小于像素的接缝，轨道真实坐标未修改；州和县界降到铁路图层之下并调淡，避免柏林行政边界的折线被误认为中断的铁路。
- 新增柏林区域真实浏览器绿色底网点击回归、绿色**有观测**与**无观测**状态区分、筛选切换后的索引保留测试。单元测试断言官方轨道始终可点，不会产生虚假百分比。

## 跨基础设施编号的列车线路走廊（2026-10-10）

- 一个列车线路（如 RE4）可能行经不同 DB InfraGO 基础设施编号。单看编号会错误地把 Wustermark—Elstal（6107）与柏林 Staaken—Spandau（6179）分成不相关的短路段。新增 `js/rail-service-groups.js`：先要求可靠、占主导的相同列车线路标记（`label_hints`），然后核实实际轨道的地理邻近和方向端点，并对岔路歧义设置唯一最近延续约束。
- 这层仅负责**点击时的运营走廊汇总**；底图与实际已观测的红、橙、绿着色保持原样。两项指标按整个已观测走廊的原始次数重新计算，绝不为中间无观测轨道填补百分比。跨编号但缺少可核实完整官方轨道路径时最多作为逻辑上的统计分组，不生成轨道折线。
- `getCorridors()` 保留同风险等级的物理区段用于独立风险研究；`getServiceCorridors()` 是跨铁路基础设施编号的选择性分组，两者不可混为全国线路总量。当前区域列车样本约54处跨编号归并，合并后约594个可点击的运营走廊。样本量及合并数会随选定运营类别、统计指标变化。
- 浏览器回归必须验证点击 Wustermark—Elstal 小区段可打开包含6179号线的 RE4 大区段，且原有颜色和没有数据的绿色铁路仍然正确可点。

- 无观测绿色轨道点选时，不仅拾取单个短来源几何：根据点击坐标沿**相同官方线路编号、无岔路歧义的真实节点链**最多延伸约22公里（`RouteGraph.walk`），使高亮呈现合理的连续轨道段；不得跨越不同编号或人为直线补线。

## 公开地图：城市—城市客运走廊（2026-10-10）

- **公开地图与研究数据已分层**：主地图不再下载或绘制完整33,547段 DB InfraGO 轨道几何。这些数据保留在仓库与旧研究页供复核。因为非客运设施、无观测支线和站内小岔线不能作为准点地图的可视线路；官方线路编号单独存在不代表有客运统计。
- 公共图绘制由 `js/rail-city-corridors.js` 生成的客运观测图：同一设施编号、同一物理站间公里区间的双向和不同车次客运观测合并为一组。沿真实站名连通图，在城市站点、中央车站、岔路或终点切分；仅绘制达到至少100次观测门槛、形成城市之间足够长的线路。单个孤立小站间、同一城市内部和不足显示长度的碎线**只从公共图隐藏**，研究数据不删除。
- 地图线色是整个可见城市间走廊原始到站/计划配对次数加权后的综合风险等级（绿/橙/红），点击可选中整段并查看两个比例。原始单站对数据保留在二级详情。不同地理路段可能有局部差异，城市走廊汇总不代表每米轨道独立运行概率。
- 局部几何只使用实际站间观测中包含的铁路线曲线；当相邻站间没有观测，不绘制凭空的连接线，也不会由两侧准点率推断其数值。此图不是完整铁路基础设施图。
- 类别仍为 RE/RB、ICE/IC等、其他运营商；公开图固定采用**综合**延误与停靠取消门槛，不再提供复杂的关注指标/最低样本控件。
- `tests/unit_core.cjs` 和 `tests/smoke_overview.py` 需检查 Erfurt–Arnstadt–Ilmenau 人口城市沿线的转乘站切分、双向同物理站间次数合计、统计加权、隐藏零散设施及各类别/桌面/手机点击操作。测试结果含现有4218条RE/RB有效观测、2128个独立站间物理边、约451条公开显示的城市间走廊；这些是2026年9月当前版本统计，不代表永久线路数量。

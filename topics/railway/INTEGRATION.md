## 状态与目的

此目录是在 **2026-10-09** 依据独立铁路专题提供的《德国铁路线路查询地图_v05.html》整理的**集成参考快照**。当前另一个专题对话可能继续更改铁路地图，此处不假定 v05 为最终成果。

集成预览有真实线路，供统一视觉与接口测试使用；**GitHub main 导航没有铁路入口，未加入 Pages 发布的验收路径，亦不得提前声称铁路专题已发布**。

## 已有资料与已确认的规模

来源作者标注 DB InfraGO 铁路基础设施的官方 CSV（WGS84 线几何），压缩后以便在浏览器显示。德国联邦开放数据目录 [GovData：Infrastrukturdaten der DB InfraGO](https://www.govdata.de/suche/daten/infrastrukturdaten-der-db-infrago?ids=b88d0ec0-dbab-4990-8539-6461f32df53b) 确认存在官方 CSV/GeoPackage、数据期为**2026年5月**，CSV资源标注**CC BY 4.0**。但**尚不能证明原型使用的恰好是这份2026年5月的 CSV**，仍须以原始文件名、下载 URL、散列及字段/数量核对再确认数据来源和适用许可。不要将另一套 BKG 受限制发布的地图产品混同于此开放数据集。

## 适配协议（前后分离）

`data/network.js` 为临时的数据快照，设置：

```js
window.GermanRailway07Data = {
  routes: [],
  sections: [],
  states: {},
  summary: {},
  qa: {}
};
```

单条 `routes` 为 15 项定长数组（沿用铁路原型的索引）：

| 索引 | 含义 |
| --- | --- |
| 0 | 官方 `Streckennummer`（**基础设施线路编号，不是 ICE 车次**） |
| 1 | 官方线路德文名 |
| 2 | 中文常用名（可能为空） |
| 3 | 方向轨道线段长度累计公里数，不是去重营业里程 |
| 4 | 官方线路原始来源分段数 |
| 5/6/7 | 电气化 / ≥200km/h / 速度未知 的累计分段公里数 |
| 8 | 该线路关联州代码数组 |
| 9 | 显示坐标系中的线路包围盒 `[xmin,ymin,xmax,ymax]` |
| 10 | 按方向分类的累计里程对象 |
| 11 | 可绘制几何部件数 |
| 12 | 官方运营点采样数组 `[站名,类型,x,y]` |
| 13/14 | 双线、单线属性累计公里数 |

`sections` 为 `[routeIndex, sourceId, electrificationCode, speedClass, trackClass, packedPolyline]`；`packedPolyline` 需要采用现有 polyline 差分编码（10 倍整数比例）。**不得把二维折线误接成站点间直线**。

原原型把 WGS84 经纬度按 `x=(lon-5.34)*76.5+15`, `y=(55.40-lat)*114.2+6` 映射到 790×1000 的平面。新 `topic.js` 在渲染时对每个压缩折线顶点**逆变换回 WGS84**，交给 Leaflet 按地图投影绘制；这样和主站 OSM 底图的城市、州界、缩放可以对齐。几何属性仍源于原型的线路（已含显示用简化），并未根据行政区重画。

## 统一视觉与交互合同

- 顶栏：与 01–06 同级的圆角专题导航，铁路主题单独高亮；**正式发布时才向五个已上线页面加入第六个入口**。
- 主体：主站相同的**左大地图／右深色信息栏**、卡片间距与按钮；移动端改为上下布局。
- 底图：与 01–06 一致的免密钥 OSM 街道地图、官方16州轮廓、`CrimeCityLabels` 中文地名层。OSM瓦片失败时仍显示铁路线路。
- 主内容：**真实轨道折线**，按速度、电气化、单双线属性着色，不能用铁路省州评分冒充单条线路实况。
- 右栏：线路编号／德文名／有证据的中文名、原始分段数、几何部件、按方向属性累计公里、运营点样本。线路搜索支持编号及原德文名。点击轨道可选中真实线路。
- 删除独立原型的第三栏、巨大 DB 标志、版本水印、自定义地图画布操作按钮。地图缩放和移动统一交给 Leaflet。
- 用户可展开数据口径，不能将双向轨道累计公里与去重营业里程混淆。
- **基础设施数据不包含准点率、临时停运、车次取消率**。未取得与线路相对应的运营级数据和明确的匹配规则前，不生成这些指标。

## 验收与正式接入步骤

1. 07 原专题交付最后一个数据/前端版本，并给出原始 CSV 的可核对 URL、数据发布日期和许可证/再分发依据；必要时更新 `network.js`（保持以上接口或同步更新适配代码）。

3. 通过 `topics/railway/tests/smoke_railway.py` 的桌面及手机浏览器测试，包括真实线路渲染、线段点选、搜索、速度、电气化与单双线切换、原始来源口径及无瓦片降级。
4. 在一个独立的正式发布 PR 中给已上线 5 张导航同步加 `../railway/` 链接，加入 `drugs-pages-deploy.yml` 的资源有效性检查，避免旧网页缓存。更新总站 README、每日监测。
5. 全站01–06冒烟回归全通过，并由 **现有唯一受锁保护的 Pages 发布器**发布；不建立第二个无锁 Pages 发布源。
